- 2026-06-27: **Phase 5 Mode-A live-debug resolution (MP3 + In/Out both fixed).** Instrumented `collectTimelineAudio` (returns a `debug` blob, also dumped to `$TMPDIR/reels-mode-a-debug.json`). Live data showed: (1) **Resolve's render API has NO MP3 format** here — `GetRenderFormats()` lists no mp3, `GetRenderCodecs('mp3')` empty, and `SetCurrentRenderFormatAndCodec('mp3','mp3')` → `errorCode:2 Unknown render codec/format combination`; the only pure-audio format is `Wave→wav`. (2) **`GetMarkInOut()` OMITS the `in` field when In=0** (`{video:{out:9792}}`), so the old `typeof v.in!=='number'` guard dropped the range → whole-timeline render. **Fixes:** render **WAV @ 48 kHz** (`wav`/`LinearPCM`) over the In/Out range, then **transcode to MP3 320 kbps / 48 kHz via the bundled ffmpeg** (`libmp3lame` confirmed present) — best-effort, WAV fallback; `timelineRenderRange` now treats a missing `in` as 0. resolve.js gained `child_process`+`paths` requires and a `transcodeToMp3` helper. transcription re-extracts to 16 kHz mono regardless, so format is purely the user's output spec.
- 2026-06-27: **Phase 5 Mode-A render format = MP3 320 kbps / 48 kHz (user-directed).** `collectTimelineAudio` now sets `SetCurrentRenderFormatAndCodec('mp3','mp3')` + `AudioSampleRate:48000`. Web-checked the Resolve scripting API: `AudioSampleRate`/`AudioCodec`/`AudioBitDepth` are documented `SetRenderSettings` keys but **there is NO documented audio-bitrate key** — so 320 kbps is passed best-effort as `AudioBitRate:320000` (honored where supported, else the MP3 codec default applies; the reliable 320 path would be a saved render preset + `LoadRenderPreset`). Format is the user's output spec only — transcribeVideo re-extracts to 16 kHz mono PCM regardless. Exact codec id (`'mp3'`) to confirm live via `GetRenderCodecs('mp3')`. Sources: wiki.dvresolve.com scripting-api, electron-rotoscope DaVinciResolve-API-Docs.
